These rules replace conflicting Cursor-specific mechanics in the skill and its references. Preserve the skill's investigation, teaching, and writing methods.

- Use tools actually available in the current environment. Cursor-specific task tools, model slugs, and model-role files are not requirements here. Follow the host's delegation rules and the user's model choices. When delegation is unavailable or unauthorized, perform the named review lenses or investigation passes directly and report that limitation; do not claim independent review.
- Discover connected sources from available tool metadata. Missing sources are evidence gaps. Never assume git, GitHub authentication, transcript access, or a connector exists.
- For T3 history, search threads scoped to the current project, then read each selected thread before relying on it. Follow the host's thread-link formatting. Use Cursor transcript paths only inside Cursor. Otherwise use an explicitly supplied workspace transcript or the current conversation; state any history limits. Never scan unrelated projects or export private transcripts into this repository.
- Resolve skill paths through the host's skill catalog. `create-skill` means the available `skill-creator` workflow. `unslop` means apply the host's plain-language writing guidance; it is not an installation dependency. If `how` is unavailable, inspect the actual code and trace entry points, data flow, ownership, and observable behavior directly. `why` is bundled alongside these skills. Do not assume other skills or playbooks are installed.
- Use `$CODEX_HOME/skills` (default `~/.codex/skills`) for personal Codex skills, or the user's selected repository. Check that location for existing mode skills. Do not write to plugin caches. Follow the installed skill-creator's supported frontmatter and invocation policy instead of copying Cursor-specific metadata.
- A request to investigate, recall, teach, reflect, or draft a mode does not authorize messages, ticket creation, pushes, or publishing. Keep backlog suggestions in the report unless external writes were requested. Apply the host's authorization rules, including existing authorization, to skill edits and Git operations.
- For structural enforcement, prefer architecture, types, lint, or scripts over another prose rule. Keep speculative findings separate from supported ones. Concrete warehouse names, schemas, and MCP commands in source references are examples: inspect the actual source before using them.
- Use the host's question tool when available. Ask only questions that affect the result and cannot be answered from evidence. Do not require unsupported multi-select controls or a fixed interview sequence.
